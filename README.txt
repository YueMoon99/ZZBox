舟舟工具箱（ZZBox） v0.7.0  使用说明
==================================================

【怎么打开】
  双击 本文件夹里的 ZZBox.exe

  不需要 Python，不需要 FFmpeg，不需要联网。
  整个 ZZBox 文件夹可以拷到 U盘 或别的电脑直接用。

  （根目录的 启动.bat 也能开，它内部就是去调那个 exe，留着当备用入口）


【关闭窗口 = 缩到托盘，不退出】

  点右上角 X 只是把窗口收起来，程序继续在后台跑：

    · 正在压制时关窗口，压制不会中断，压完会弹通知告诉你结果
    · 屏幕右下角（Windows 11 在 ^ 里）会出现蓝色图标，那是它
    · 双击托盘图标 / 左键单击 = 把窗口叫回来
    · 右键托盘图标 = 菜单：
          第一行是当前状态和进度（灰色，不能点）
          显示主窗口
          开始压制        （窗口收起来后也能直接开压）
          取消当前任务    （有任务在跑时才亮）
          退出            ← 这是唯一真正退出程序的地方
    · 鼠标悬停在托盘图标上，能看到「舟舟工具箱 · 45% · 文件名」

  想让它一直待在任务栏上：Windows 11 的 ^ 里把它拖到任务栏外即可
  （系统默认把新图标收进折叠区，不是程序的问题）。

  如果正在压制时点退出，会先弹一次确认，避免误操作中断任务。


【怎么用】
  1. 顶部先选工作台：「视频处理」「图片处理」或「PDF 处理」
     这三边是三套完全独立的东西 —— 各自的队列、各自的参数、各自的状态。
     只拖视频或只拖图片进来时，程序会自动切到对应的那一栏；
     拖 PDF 进来会自动切到 PDF 处理。
     「输出到」那一行是三个工作台共用的，切过去不用重填。

  2. 把文件拖进窗口，或点队列右上角那个「+」

  3. 选页签（队列下面那排）：
       视频处理 →  「视频压缩」把片子压小
                   「AI 增强」 超分辨率放大 / AI 补帧
       图片处理 →  「图片压缩」改格式、压体积
                   「AI 超分」 放大 2~4 倍
       PDF 处理 →  没有页签，页面格墙，右键菜单里做所有操作

  4. 参数都在下面那一块面板里，一行一组，左边是名字：
       视频压缩：  编码器 · 音轨 / 质量 · 缩放
       视频 AI ：  超分 · 模型 / 补帧 · 输出 / 编码 · 画质
       图片压缩：  格式 · 质量 / 长边 · 元数据
       图片 AI ：  倍率 · 模型 / 格式 · 画质
       PDF 压缩：  质量（点右键「压缩选中…」后才出现）
                   图片的格式 / 长边跟随「图片处理 → 图片压缩」

     面板最下面那行写的是「这次会输出成什么」：尺寸、格式、预计体积、
     临时空间、预计耗时。改任何参数，那一行和上面的表格会同步重算。

  5. 点右下角开始（按钮文字会跟着页签变：开始压制 / 开始增强 /
     开始超分 / 导出）

  6. 进度条显示百分比；做完的行，状态圆点会变绿


【AI 增强：把 720p 放大到 1080p / 4K，或者补帧到 60fps】

  切到「AI 增强」页，右下角的按钮会变成「开始增强」。参数分三行：

    超分 —— 关闭 / 2× / 3× / 4×
            输出尺寸就是源尺寸乘以这个倍数，没有第二个尺寸开关：
            720p 选 2× 就是 1440p，选 4× 就是 2880p。
            鼠标停在按钮上会显示「这一档会得到多大、显存够不够」，
            面板里还会写「根据你的显卡推荐哪一档」。

    模型 —— 先看你的素材是什么：
              「真人实拍」realesrgan-x4plus —— 默认，1670 万参数，能重建
                          皮肤纹理、发丝分层、镜架金属感。慢：约 6 秒/帧
              「动画番剧」realesr-animevideov3 —— 只有 1.4 MB，快 5 倍。
                          它只认动画帧，拿去处理真人会把脸抹成色块、眼睛
                          描成卡通线条

    补帧 —— 关闭 / 2× / 4×
            RIFE 光流插帧。只改帧率，不改时长，音轨原样保留。
            30fps 的片子选 2× 就是 60fps。

    编码 —— H.264 / HEVC / AV1，以及降噪 / 锐化两个开关
              降噪：低码率片子先轻度去噪再超分，别把压缩块一起放大 4 倍
              锐化：默认轻度。4× 重建后缩到目标尺寸，边缘会软一档，
                    补一点 unsharp 拉回来；开到「较强」会开始出白边

    面板最下面 —— 引擎状态、显存档位、推荐档位、输出规格、预计耗时，
                  以及一行橙色提醒：这次会产生多少 GB 临时文件、
                  那个盘还剩多少、为什么别把输出放系统盘

  关于「2×」这件事，有个地方容易误解：

    实拍模型只有 4× 一档，但你选 2× 不会拿到一个 4× 的片子。
    它的做法是：按 4× 推理到 2880p → lanczos 降到 1440p → 输出 1440p。
    多这一步不是浪费，是超采样 —— 先在 4 倍尺度重建细节再缩回去，
    锐度明显好过任何原生的 2× 模型。这也是它慢 5 倍的价值所在。

  几个要注意的地方：

    · 显存不够时靠缩小分块（tile）兜住，而不是悄悄降倍率。
      6G 卡选 4× 也能跑完，只是会明显变慢。
    · AI 增强要落盘一堆中间帧（引擎只吃图片目录，没法走管道）。
      面板上会写清「临时空间 X GB」，开始前还会检查磁盘够不够。
    · 处理期间会占满显卡，别同时开游戏。可以取消，取消会清掉临时文件。
    · 一个文件处理完，临时帧序列立刻删掉，不会堆到整批结束。
    · 文件名叫 _AI_1440p_xxx.mp4 这种，按实际输出分辨率标，
      不写容易误导的「2x / 4x」。

  输出格式说明：
      成片统一是 8bit yuv420p + bt709，任何播放器、手机、剪辑软件都吃得下。
      中间会拆成 PNG 序列，所以拆帧和合成两端的色彩转换系数是写死的同一套，
      色彩不会跑偏。如果你拿到的成片整片发绿、白的地方变粉紫，那是旧版本
      0.7.0 的 bug（像素格式编成了 RGB），换这一版重跑即可。

  效果预期（说实话版）：
      720p → 1080p     用实拍模型，皮肤纹理和发丝是真的能回来
      720p → 1440p     最好的一档，细节和自然度平衡得最好
      720p → 4K        细节仍有相当一部分是模型猜的，
                       人脸/文字/细纹理最容易翻车
      动画、番剧、AI 生成的片子适合冲 4K；真人实拍建议停在 1440p

  速度参考（RTX 4060 8G，实拍模型）：
      3 秒 720p 素材走完「超分 2× + 补帧 2×」约 5 分钟
      1 分钟素材大概 2.5~3 小时
  慢，但只跑一次。嫌慢可以先只补帧 —— 那个很快，1 分钟素材约 1 分钟。
  界面上的「预计耗时」就是按这张卡的实测基准算的。


【图片处理：批量改格式、压体积、放大】

  顶部切到「图片处理」。队列和参数面板跟视频那边是一个模子刻的，
  只是参数换成了图片相关的。

  「图片压缩」页：

    格式 —— 保持原样 / JPG / PNG / WebP
            保持原样 = 每张图各按自己的格式走，只改质量和尺寸

    质量 —— 40~100 滑块，默认 82。
            JPG 和 WebP 有效；PNG 是无损的，这个值不参与

    长边 —— 不改变 / 1920 / 1280，也可以在最右边自己填像素。
            只缩不放，等比缩放，长的那条边不超过这个数

    元数据 —— 保留 / 清除。
              清除会去掉 EXIF、拍摄时间、GPS 和相机型号 —— 发图前建议清掉

  几个自动处理的地方，不用你操心：

    · 带透明通道的图转 JPG 时，透明区会先摊到白底上，不会拿到一张黑底图
    · 手机竖拍的照片（EXIF 里记着「转 90°」），输出是正的，不会躺倒
    · 一张图大约 0.1 秒，几百张也就几分钟

  「AI 超分」页：

    倍率 —— 关闭 / 2× / 3× / 4×
    模型 —— 真人实拍 / 动画番剧，和视频那边是同一套模型，语义完全一样
    格式 —— 跟随源 / PNG / JPG / WebP
    画质 —— 降噪、锐化两档，默认「关 / 轻度」

    「2×」在图片这边也是超采样：实拍模型只有 4× 一档，你选 2× 时它按
    4× 推理，再缩到 2× 的尺寸。多出来的那一步不是浪费，是让边缘更锐。

    速度：RTX 4060 上，1280×720 的图约 8 秒一张，1920×1080 约 18 秒。
    界面上会按张数报「共 N 张 · 每张约 X 秒」，点开始前就能估出总时间。

  图片不走视频那套「拆帧 → 处理 → 合成」，因为图片本来就是单帧：

    · 不占临时帧序列空间，一张图最多两步命令
    · 中间文件就在输出目录里，处理完立刻删掉，不会留一堆 png
    · 文件名叫「原名_压缩.webp」「原名_超分2x.jpg」，
      标的是你要的那个倍率，不是引擎实际跑的倍率

  两个页签是两套独立操作：压缩完切到超分页，可以直接再跑一遍，
  不用手动去点「重提所选」。


【PDF 处理：按页重排、合并拆页、压缩】

  顶部切到「PDF 处理」。这一栏的队列换了模样 —— 不是表格，是一格一页
  的缩略图墙：

    · 拖一份 80 页的 PDF 进来，就是 80 个格子
    · 拖图片进来，一张图也是一格
    · PDF 和图片可以混在一个队列里，导出时按队列顺序来

  格子墙怎么操作：

    多选     —— 单击、按住 Shift 连选、按住 Ctrl 加选
    排序     —— 按住格子拖到新位置
    缩放     —— 按住 Ctrl 滚轮，92~268 像素
    撤销     —— Ctrl+Z，旋转 / 导出 / 压缩 / 删除 / 排序都能回退
    删页     —— 右键「删除选中」，只动队列，源文件不碰

  每格文件名下面显示大小：PDF 页写「pdf文件」，图片写「371 KB」；
  压缩调参时变成「371kb→101kb」，拖质量条实时变化。

  所有页面操作都在**格子墙的右键菜单**里（面板上不再有按钮）：

    「旋转选中 90°」 选中的页面顺时针转 90°，再点继续叠加
    「导出选中…」   把选中的页面导出。弹出来的菜单里选：
                     · 导出为 1 个 PDF（几页合成一份）
                     · 导出为多个 PDF（每页一个）
                     · 导出为 PNG / JPG 图片（每页一张）
    「压缩选中…」   先进入调参状态，不会立刻动手
    「删除选中」    只从队列移除，原始文件不动
    「全选」「撤销 Ctrl+Z」

    ★ 单页文件的文件名跟原文件走：`年度报告·3.pdf`（3 是这页在原文件
      里的页号），图片不带页号，就是 `票据扫描.png`。重名自动挂 (2)，
      不会把上一次导出的文件覆盖掉。

    ★ 导出选中和合并都不会重新渲染：文字层、链接、表单、书签原样保留，
      导出的 PDF 照样能搜索、能复制。JPEG 图片也是原样嵌进去，一个
      像素都不重算。

    点「压缩选中…」之后，下方才出现质量滑块（30~100，默认 78）和
    「确认压缩 / 取消」。拖滑块时格子上的数字实时变，点确认才真压，
    压完静默换进队列、压缩条自动收起。PDF 页只重编码内嵌图片；
    图片走「图片处理 → 图片压缩」同一套方案（格式 / 质量 / 长边 / 元数据）。

    压缩这一版只动图片，不碰页面：

      · 页面尺寸不变（A4 还是 A4）
      · 文字层保留 —— 压完还能搜索、还能复制
      · 图片像素宽高跟随图片压缩的长边设置，默认不变
      · 链接、书签、表单都还在

    压缩结果以临时文件形式放在 ZZBox 软件目录里，绝不覆盖原文件；
    导出时直接用这些临时件，退出软件（托盘右键「退出」）时整目录自动删。
    按 Ctrl+Z 可以把队列换回压缩前的样子。

    ★ 压过的页面右上角会挂一个绿色「已压缩」小标，一眼看出哪几页压过。
    ★ 压过的页面还能再压一次：右键「压缩选中…」调更低质量，第二轮从
       上一轮的压缩件继续压，不是在原始文件上重来，能一层层往下减。
       每轮缓存按「时间_轮次」分开存（181231_r01、r02…），同一秒连压
       两次也不会互相覆盖。Ctrl+Z 逐轮回退：撤一轮回上一轮压缩件，
       再撤一轮回原始文件，绿标跟着增减。

    预估是真解码真编码算出来的，不是估的。图片多的文件在后台算，
    界面不卡，数字一格一格跳出来；大尺寸扫描页可能要几秒。
    纯文字页会直接显示「本页无图片」，不会一直挂「估算中…」；
    点确认时会跳过这些页。估算出错会显示「估算失败」。

    ⚠ 纯文字页没有图片，压了等于没压。
    ⚠ 印刷设计稿（CMYK、带透明蒙版的图）现在照常压：只重编码颜色
       通道，蒙版原样留着，透明度不变。实测一页 378 KB → 168 KB，
       颜色同向偏差 < 0.02/255，看不出差别。
    ⚠ 蒙版图、JPEG2000、特殊色彩空间仍会跳过（原样保留）。
    ⚠ 改了质量，之前压好的临时结果自动作废，需要重新压。

  实测参考：两页 1600×1200 的扫描件，图片 2.8 MB → 1.1 MB（省 59%），
  文字层和页面尺寸完全没变。

  不支持的：带打开密码的 PDF、加密导出、OCR、转 Word。


【文件队列：一张表格，看得见体积】

  队列是一张六列表格，从左到右：

      文件名        双击这一列没反应，纯文本；太长会中间省略，鼠标悬停看全名
      原始格式      分辨率 · 帧率 · 时长，例：1920×1080 · 25fps · 03:29
      导出格式      同上，只是分辨率会跟着「缩放」变，帧率和时长不变
      原始大小      源文件体积
      预计导出大小  按当前编码器 / CRF / 缩放算出来的成片体积
      操作          状态圆点 + 状态文字 + 锁定 / 重提 / 删除

  改任何一个参数（编码器、CRF、码率、缩放），「导出格式」和「预计导出大小」
  两列会当场重算，不用等开始压。

  「预计导出大小」是怎么来的、准不准：
      按 CRF 与分辨率推算出视频码率，再加上音轨（AAC 160k）算总大小。
      这套系数是用你那份实拍素材实测标定的，回测六组设置误差都在 1% 内。
      但它是"同类素材"的统计规律，实拍里运动多、噪点多、场景切换密集的
      片子实际会偏大一些，通常 ±25% 浮动；用「码率」模式时最准，因为目标
      码率就是你直接指定的。把它当成"量级参考"，不要当成精确值。

  状态圆点：

      黄色  就绪     已入队，等待压制
      灰色  已锁定   不参与任何队列动作（用来临时跳过某几个）
      蓝色  压制中   正在编码，后面会跟着百分比
      绿色  已完成压制 / 已抽取音频 / 已删除音轨
              该行已经处理过，不会再被重复压
      红色  失败     编码出错或被手动停止

  行尾三个按钮：

      锁定   点一下变「已锁」，该文件不参与压制；再点一下解除
      重提   把状态重置为「就绪」并解除锁定，可以再压一次
              （已完成、失败的文件想重压，就点它）
      删除   从队列里移除，不影响硬盘上的源文件

  拖动排序：按住某一行上下拖，松手即可调整顺序，队列按新顺序压制。
  压制过程中不能拖动、也不能删除正在压制的那一行，避免队列错位。

  多选：
      · 单击选中一行；Shift 连选一段；Ctrl 加选 / 减选用在零散的几行
      · 在表格下方的空白处按住左键拖出一个框，框住的行就被选中
      · 选中之后，右上角的「重提所选」「删除所选」只作用于这几行

  右上角按钮：
      +          添加文件（也可以直接把视频拖进来）
      重提所选   把选中的行重置为「就绪」，可再压一次
      删除所选   把选中的行移出队列，不影响硬盘上的文件
      清空       清空整张队列

  右下角按钮：
      抽取音频   把所选（没选就全部）文件里的音轨导出成 .m4a
      删除音轨   只剥掉音轨，视频流原样拷贝、不重新压制
                 输出为「原名_无音轨.mp4」，源文件不动
      两个工具都是批量的：勾几行就处理几行，跑完状态分别是
      「已抽取音频」「已删除音轨」，产物默认落在「输出到」的目录里。

  列宽：把鼠标移到两个表头之间，按住左右拖（和资源管理器一样）。
        拖的时候只有这根线左边那一列变宽变窄，它右边所有列整体跟着平移，
        被拖的线始终贴着鼠标走。
        列宽的总和始终等于窗口宽，可拖动的余量由窗口宽度决定；操作列窄到
        刚好放得下指示灯和三个按钮就顶住，所以按钮永远不会被挤出可视区。
        窗口拉宽后余量会自动补给「文件名」列。
  表格高度：默认能看见 3~4 行，窗口拉高时跟着长高；
  文件多到装不下时右侧出现滚动条，鼠标滚轮可直接滚动。
  队列为空时表格中间会有一行提示文字，不会只剩一条光秃秃的表头。

【输出在哪】
  默认输出到源文件所在的文件夹，

【关于体积：为什么同样的 CRF 比小丸大】

  v0.2 已修好，根因有三条。如果你之前压出 190MB、小丸只有 60MB，看这里：

  1) CRF 和 CQ 不是一个东西（主因）
     x264 的 CRF 是逐帧逐块自适应的感知质量；显卡只有 CQ，它只是给编码器
     一个质量提示。旧版按 crf-2 换算，方向反了——等于把小丸的 CRF25
     当成 CQ23 的高画质档来压，自然会大。

     实测（你那份实拍素材 30 秒切片，以 x264 CRF25 为画质基线）：
        设置                视频码率    画质SSIM   体积
        x264 CRF25（小丸）   3.49 Mbps  0.9885    1.00 倍
        旧版 等效 CQ23       7.60 Mbps  0.9940    2.18 倍
        新版 等效 CQ28       4.23 Mbps  0.9889    1.21 倍
     新版的 1.21 倍是硬件编码的固有代价（同画质下 NVENC 天生比 x264 多花
     15%~25% 码率），不是参数没生效。

  2) 音轨被原样搬过去了
     .mov 工程文件的音频常是 PCM 24bit，码率 2~3 Mbps。三分钟的片子光音频
     就 60MB。现在默认转 AAC 160k，并且源音频超过 256kbps 时即使选
     「保留原样」也会自动降级，界面会给出提示。

  3) 编码器没选对
     同画质下的体积：H.264 100%  /  HEVC 约 88%  /  AV1 约 75%


【想压得更小，怎么设】

  想 ≈ 小丸 CRF25 的体积      →  HEVC + CRF 26
  想再小 25% 左右              →  HEVC + CRF 29
  想再小且能接受兼容性风险     →  AV1 + CRF 26
  想极致小                     →  CPU x265 工具（如 ShanaEncoder），
                                  比本工具再小 25%~35%，代价是慢十几倍

  实测对照（同一段 30 秒素材，含 AAC 音轨，基准为小丸 CRF25）：
        H.264 CRF25  → 1.27 倍
        HEVC  CRF22  → 1.61 倍
        HEVC  CRF26  → 0.98 倍
        HEVC  CRF28  → 0.77 倍
        HEVC  CRF29  → 0.68 倍
        AV1   CRF25  → 0.93 倍

  CRF 滑块下方现在会直接写这组话（接近无损 / 高画质 / 均衡 / 小体积 /
  极小体积），不用再靠猜。

【顶部那个绿色标签】
  显示你的显卡和可用的编码器。
  点它可以看到详细的环境自检信息（显卡型号、驱动版本、FFmpeg 版本）。
  如果它是红色，说明环境有问题，点开截图发我。


【出问题了怎么办】
  1. 任务列表里显示「失败」——鼠标悬停在「失败」两个字上，会显示原因
  2. 启动时弹「启动失败」窗口——里面会写出日志文件路径，把那个文件发我
  3. 其他异常 —— 截图发我

  日志位置：本文件夹\logs\error.log


【想确认程序本身没坏，可以这样自检】
  按住 Shift 右键点本文件夹空白处 →「在此处打开 PowerShell 窗口」
  输入：.\ZZBox.exe --selftest
  它会自动生成一段测试视频、压一遍，再生成一张测试图、压一遍并超分一次，
  最后把两张图合成一个 PDF、读回来、渲染一页。
  出现 RESULT = PASS 就说明显卡、编码器、FFmpeg、AI 引擎、PDF 库全部正常。

  （PDF 那一项尤其值得看：打包时 pdfium.dll 容易漏收，源码跑得好好的，
   一点 PDF 就报 cannot load library —— 有这一段就能在发版前发现。）


【这一版已知的限制】
  · 解码用 CPU、编码用 GPU。全 GPU 管线（硬解 + 显存内缩放）还没做
  · HDR / 10bit 素材会被转成 8bit，颜色可能不对
  · 队列是串行的，同时只压一个文件（GPU 并发反而更慢）
  · 没有暂停功能，只能取消整个队列
  · AI 增强的补帧只能整数倍（2×/4×），24fps 直接补到 60fps 这种做不到
  · AI 增强的输出尺寸严格等于「源尺寸 × 倍率」：720p 选 4× 就是
    5120×2880。不会偷偷改小，也不会弹「超过 4K」的提示
  · AI 增强需要显卡支持 Vulkan（RTX 20 系及以上都行）；引擎缺失时
    普通压制不受影响，只有点「开始增强」会提示缺哪个
  · 图片不支持动图：GIF 不在支持列表里（直接处理会压成第一帧，干脆不收）
  · 图片超分没有分块尺寸自适应，输出超过 8000 万像素可能撞显存
  · 图片队列和视频队列各自独立，不能混排成一条流水线
  · PDF 压缩只作用于页面里的图片：纯文字页没有收益
  · PDF 里图片的像素尺寸跟随图片压缩的长边设置，默认不变
  · PDF 压缩对纯文字文件反而变大 —— 检测到就劝退，但不阻止
  · PDF 不支持带打开密码的文件，也没有加密导出
  · PDF 不做 OCR、不做文字编辑、不转 Word
  · PDF 导出不保留书签目录（页面被重排后原页码已经对不上）
  · PDF 处理不需要显卡，纯 CPU，任何 Windows 机器都能跑
