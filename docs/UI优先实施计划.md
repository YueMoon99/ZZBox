## 一、先看你这台机器（已实测）

| 项 | 结果 | 含义 |
|---|---|---|

## 二、交付与测试方式（关键变化）

每个阶段交付一个**带版本号的独立程序**：

```
GPU压制_v0.1/  ← 整个文件夹给你
  ├─ GPU压制.exe      ← 双击这个
  ├─ bin/ffmpeg.exe
  └─ README.txt
```

你的操作永远是三件事：**双击 → 点几下 → 看结果**。

我需要的反馈也永远只有一种：**截图**，或者点程序里的「导出诊断包」按钮，把生成的 zip 发我。你不用描述参数、不用看报错文字。

## 三、阶段划分

### P0 · 能打开的第一版（0.5 天，v0.1）

**做什么**
- 下载带 NVENC 的 FFmpeg 放进项目
- 搭出主窗口（见线框图）
- 首页「环境自检」卡片：显卡型号、驱动版本、三种编码器是否可用、FFmpeg 版本
- 双击 `启动.bat` 出窗口

**你能测**：能不能正常打开？显卡和编码器有没有被正确识别？

> 这一版不可转码，但它验证了最关键的前提：你的机器到底能不能跑 GPU 编码。

---

### P1 · 单文件完整流程（2 天，v0.2）

**做什么**
- 拖入 / 选择文件，读出 分辨率·时长·编码·码率·音轨数
- 参数面板全部可点：编码器、CRF 滑块、缩放百分比、输出目录
- 进度条 + 速度 + 剩余时间 + 取消
- **先只接通 H.264 NVENC 一条通路**，确保一次成功，不贪多

**你能测**：拿一个常用视频，选好参数点「开始压制」，等它出片。重点看四件事：
① 有没有生成文件 ② 时长对不对 ③ 画质能不能接受 ④ 速度多少（记得截图那个 8.3× 的数字）

---

### P2 · 质量与缩放真正生效（2 天，v0.3）

**做什么**
- 接通 HEVC / AV1 编码器
- 恒定码率模式（CBR / VBR 两档）
- 百分比缩放真实生效，宽高自动取偶数，不超源分辨率
- 出片后自动回读实际参数，界面上显示「实际输出 1920×1080 · HEVC · 3.2 Mbps」——**这是防止参数没生效的唯一可靠手段，必须有**

**你能测**：同一个文件用 CRF 22 跑一次、码率 6M 跑一次，比体积。按 50% 缩放跑一次，看是不是正好一半且不变形。

---

### P3 · 批量队列（2 天，v0.4）

**做什么**
- 多文件入队、拖动排序、一键套用同一套参数
- 串行执行（同时只跑一个，这是 GPU 编码的正确姿势）
- 单任务取消 / 整队暂停 / 失败自动重试一次 / 失败原因中文显示
- 队列状态存盘，关掉软件再开还在

**你能测**：一次拖 10 个文件进去，点开始，然后去干别的事，回来看是不是全绿。

---

### P4 · 音频与音轨（2 天，v0.5）

**做什么**
- 音轨列表（语言、声道、编码、码率）
- 抽取音频：原样导出 m4a / 转 MP3
- 删除音轨、只保留指定音轨
- 「仅换封装不重编码」模式（秒级完成，适合只改容器格式）

**你能测**：抽一个 m4a 出来播放；删掉全部音轨后确认视频没声音。

---

### P5 · 又快又稳（3 天，v0.6）

**做什么**
- 全 GPU 管线：硬解（NVDEC）+ 显存内缩放（scale_cuda），帧不落回内存
- 10bit / HDR 元数据透传，防止输出泛白偏色
- 显卡不支持某项能力时自动降级，并明确告诉你降级了什么
- 所有常见错误翻译成人话：「文件损坏」「磁盘满了」「显卡被别的程序占用」

**你能测**：4K HDR 片子跑一遍看颜色；故意拖一个损坏文件进去看提示是否说得清楚。

---

### P6 · 成品（2～3 天，v1.0）

**做什么**
- 预设管理（内置「B站投稿」「微信压缩」「本地存档」，可导入导出）
- 打包成单文件 exe + 安装包，无需安装 Python
- 关于页、检查更新、日志导出

**你能测**：拷到另一台没有 Python 的电脑，双击能不能直接跑。

---

## 四、需要你只做一件事的关键决策

**UI 会反复改，这是最大的时间黑洞。**

所以：先把界面结构定死（见线框图），确认后再写代码，之后只做「加功能」不做「改布局」。你如果中途想调位置可以，但要接受多花半天。

## 五、风险与对策（针对非技术用户场景）

| 风险 | 对策 |
|---|---|
| 程序打不开 / 闪退，你无法排查 | v0.1 就内置全局崩溃捕获，弹窗给中文原因 + 导出诊断包 |
| 参数填了但没生效 | 出片后回读实际参数并显示在界面上，肉眼可验 |
| Python 打包后体积大（~80MB）/ 杀软误报 | 用 Nuitka 编译而非直接打包；后续加代码签名 |
| GPU 编码画质不如 CPU，你觉得"被骗了" | 界面上直接给出「速度优先 / 画质优先」二选一，不藏参数 |
| 换电脑后功能失效 | 环境自检页在启动时自动跑，能力不足的选项直接置灰并说明原因 |
