# 舟舟工具箱 · 发布视频脚本（100 BPM 卡点版）

> **一句话**：100 BPM 的拍网格上做一支深色底、浅色元素的功能展示片，
> 每个功能讲完停 2.4 秒再切，靠"快切 + 停顿"的呼吸做节奏，不靠堆特效。

---

## 〇、总纲

| 项 | 值 |
|---|---|
| 曲速 | 100 BPM｜1 拍 = 600 ms｜1 小节（4/4） = 2.4 s |
| 总长 | **116 拍 = 69.6 秒 = 29 小节** |
| 结构 | 开场 2 小节 + 四个功能段（各 6 小节）+ 收口 3 小节 |
| 每段 | 痛点 4 拍 → 方案 8 拍 → 细节 8 拍 → **停顿 4 拍（2.4 s）** |
| 基调 | 深色底 `#0C0D10` + 浅色元素 `#F4F5F7`，只允许一个彩色强调色 |
| 密度 | 每镜至少三层运动（主体 / 次级 / 环境），16 分音符（150 ms）级微动 |
| 切点 | 全部落在拍上，且每个镜头都从**小节线**起 |

**停顿为什么是 4 拍**：4 拍 = 2.4 秒，正好一小节。这样每个功能段是整 6 小节，
全片 29 小节，所有切点都落在小节线上 —— 鼓点的重音和画面切点永远对齐，
这是卡点片最要紧的事，比"停满 3 秒"重要得多。2.4 秒的停顿配上撤鼓，
体感上已经足够"空"，再加多半秒反而拖。

## 二、视觉系统

### 2.1 色板

```css
--bg:        #0C0D10;   /* 全片底色，比程序面板更沉，给白色元素留出层次 */
--surface:   #15171C;   /* 卡片 */
--surface-2: #1C1F26;   /* 卡片悬浮 / 选中 */
--line:      #2A2E36;   /* 1px 描边，只在需要切分的卡片上用 */
--text:      #F4F5F7;   /* 一级文字（不用纯白，纯白会过曝发虚） */
--text-2:    #9BA1AC;   /* 二级文字 */
--text-3:    #5D626C;   /* 三级文字 / 网格线 */
--accent:    #4C8DFF;   /* 全片唯一的彩色：完成、通过、选中 */
--warn:      #FFB020;   /* 只在痛点镜头出现（容量条、PSNR 红标） */
--shadow:    0 24px 60px rgba(0, 0, 0, .55);
```

**纪律**：`--accent` 全片出现面积不超过画面的 3%。Apple 的做法是整片黑白灰，
只在"这一下成功了"的时候给一抹蓝。彩色一多就掉价。

### 2.2 字体

| 用途 | 字体 | 字重 | 字距 |
|---|---|---|---|
| 标题 | `"Microsoft YaHei UI", "PingFang SC", sans-serif` | 600 | `-0.02em` |
| 正文 / 界面文字 | 同上 | 400 | `0` |
| 数字 / 代码 | `"Cascadia Mono", "JetBrains Mono", ui-monospace` | 400 | `0` + `tabular-nums` |

负字距是"苹果味"的关键：字重上去、字距压下来，标题才会显得紧致而不笨重。
数字一律 `tabular-nums`，否则滚动时左右抖。

字号（1080p）：标题 96 / 镜内标题 56 / 屏幕文字 40 / 面板文字 26 / 字幕 34。

### 2.3 分层

不用描边分隔层级，用**阴影 + 明度差**。卡片浮在底色上靠 `--shadow` 和
`--surface` 比 `--bg` 亮 4% 来区分，只有在需要"切一块出来"的地方才加 1px 描边。

边距 72 px，关键内容留在中心 1080×1080，方便裁竖版。

### 2.4 版面三层

```
背景层   形状元素，跨镜头常驻，切镜时不断流
主体层   卡片 / 窗口，硬切
注释层   左上章节号、右上段落进度、左侧注释列、提示语
```

**背景必须连续**。切镜只切主体，背景一直在飘 —— 主体硬切 + 背景连续，
是"贵"和"平"的分界线；背景跟着一起切，每个镜头都像在翻 PPT。

形状只用几何原语：圆环、圆角方框、点阵、十字、小圆点。全部**只有描边没有填充**
（点阵和小圆点除外），1px、明度压到 4%–8%，靠"看得见但说不出"的程度。

浮动幅度 **8–22 px、周期 11–17 s**，两个不同周期的正弦叠加，避免所有形状
整齐划一地一起动。**不要再加大**：到 40 px 就开始抢主体，那种"粒子到处飘"
的廉价感就是这么来的；也不要给动效元素加实时 `filter: blur()`。

**注释层是信息密度的来源**。主体之外至少要有三处文字：

| 位置 | 内容 | 作用 |
|---|---|---|
| 左上 `72,76` | `01 —— 压缩` | 告诉观众现在在第几段 |
| 右上 `right 72,82` | 四道短横，当前段加长提亮 | 段落进度，兼作节奏提示 |
| 左侧 `72, 居中` | 标签 + 数值，三行 | 把画面里的数字翻译成"这是什么" |
| 主体旁 | 一句带引线的提示 | 说主体自己说不出来的事 |

注释列的数值**必须跟主体同步**：条满了还剩 12 GB 这种自相矛盾，是这类演示片
最容易露馅的地方。注释列**不跟着镜头缩放** —— 它是版面元素，不是画面里的东西，
S3 推近时它应该纹丝不动。

提示语站位固定（主体下方 / 窗口上方 / 注释列下方三档），不要用坐标硬写：
S3 推近时窗口左边缘会扫过来，写死就会压字。

## 三、动作语法

对标 Apple 产品片和 Microsoft Fluent：**动效是解释"东西从哪来、到哪去"，
不是表演**。规则定死，才有统一的质感。

### 3.1 缓动

| 用途 | 曲线 | 时长 | 位移 |
|---|---|---|---|
| 进场 | `easeOutExpo` | 280 ms（半拍） | 上移 24 px + 透明度 0→1 |
| 退场 | `easeInCubic` | 180 ms | 上移 -12 px + 透明度 1→0 |
| 弹性落定 | `cubic-bezier(.34, 1.56, .64, 1)` | 420 ms | 过冲幅度 ≤ 4% |
| 数字插值 | `easeOutCubic` | 400 ms | — |
| 大元素（窗口） | `easeOutExpo` | 600 ms（1 拍） | 缩放 0.92→1 + blur 16→0 |
| 光带擦除 | `easeInOutCubic` | 900 ms | `clip-path` |

缓动写成**纯函数**，不要用 CSS `animation` —— 按时间点跳转时对不上。

### 3.2 三条硬规则

1. **每镜三层运动**：主体（卡片/文字）+ 次级（进度条/数字/高光）+ 环境（柔光斑漂移 / 粒子上升）。
   只有主体在动会显得空，三层一起动才"丰富"，但方向和速度必须错开，否则打架。
2. **强拍只给两件事**：切镜、大元素入场。第 2/4 拍给次级元素，8 分音符（300 ms）给小位移，
   16 分音符（150 ms）给微元素闪烁。层级乱了，卡点会变成噪音。
3. **停顿不等于冻结**。4 拍停顿里整幅画面以 `1.00 → 1.03` 极慢推近（linear，2.4 s），
   柔光斑按 8% 幅度漂移，画面再轻微下沉把构图校回中心。静中有动，观众才不觉得卡了。
   **不要在 UI 上撒粒子** —— 落在界面上的白点看起来像屏幕坏点，不是氛围。

### 3.3 光的用法

一个径向柔光斑（`radial-gradient`，`--accent` 掺 6% 白，半径 900 px，模糊已烘进渐变里），
全片只在两处出现：开场标题后方、每个功能段亮相瞬间。它按 8% 幅度、12 秒周期漂移，
是"环境运动"的主要来源。

**不要**在动效元素上实时加 `filter: blur()` —— 60 fps 无头渲染下这是最贵的属性，
一个卡片 blur 能把单帧从 6 ms 拉到 40 ms。窗口入场的 blur 只在 0–300 ms 内衰减，
之后立刻摘掉 `filter`，不要让它常驻。

## 六、声音

### 6.1 配乐

- 100 BPM，四四拍，深色向（低频厚、高频克制），不要 EDM 那种亮 lead。
- 结构：开场 8 拍建立脉冲 → 功能段鼓组稳定推进 → **每个停顿段撤鼓** → 收口只剩 pad 与低频。
- 这是全片节奏的核心手法：**用"抽空"制造停顿的重量**。鼓一直在打，停顿就只是慢；
  鼓一撤，那 2.4 秒会"沉"下来。

### 6.2 音效

| 时机 | 音效 | 说明 |
|---|---|---|
| 每小节第 1 拍 | sub kick | 冲击只给声音，画面不做缩放 —— 1080p 下整帧缩放会让中文边缘发毛边，看着脏 |
| 切镜 | whoosh | 80 ms，带轻微 pitch 上行 |
| 大元素入场 | 短 rise | 200 ms |
| 数字落定 | tick | 极短，别用"叮" |
| 完成状态 | 单音 chord | 只在超分/删音轨/压缩各一次 |
| 停顿开始 | 混响尾巴 | 让鼓的残响自然收掉 |

### 6.3 混音

配音 -14 LUFS，音乐 -18 LUFS 垫底，音效 -20 LUFS，峰值 ≤ -1 dBTP。
**静音看一遍要能看懂** —— 卡点片最容易犯的错是离开音乐就散架。

## 七、制作指导

### 7.1 规格

| 项 | 值 |
|---|---|
| 画布 | 1920 × 1080 |
| 帧率 | 60 fps |
| 时长 | 69.6 s ± 0.1 s（严格 116 拍） |
| 帧数 | 4176 |
| 输出 | H.264 / yuv420p / CRF 16 / AAC 192k 48 kHz |

### 7.2 时间轴接口

只暴露一个入口：`renderAt(tMs)`。

- 任意时刻都能完整重算，不依赖上一帧状态。
- 场景里不许 `setTimeout` / `setInterval` / `rAF` 自推进。
- 渲染路径里不许读 `Date.now()` / `performance.now()`。同一时刻渲两次，结果必须逐像素一致。
- 场景写成 `{ id, t0, t1, mount(root), update(p, tMs) }`，`mount` 只建一次 DOM，`update` 每帧改样式。
- 拍网格抽成 `beat.js`：`beatToMs(n) => (n - 1) * 600`、`msToBeat(t) => t / 600 + 1`，
  场景里所有时间都写成拍号，不写魔法数字。

验证：`renderAt(24000)` 调两次，截图逐像素一致。

### 7.3 目录

```
video-promo/
├── zzbox-promo.html     # 单文件成品，双击即看（bundle.py 生成，别手改）
├── index.html           # 源码入口：舞台 + 背景层 + 字幕 + 播放器
├── style.css
├── beat.js              # 拍网格 + 缓动纯函数 + 贝塞尔
├── timeline.js          # 场景注册 + renderAt(ms) + onFrame 钩子
├── components.js        # 主窗口 DOM、队列数据、注释列模板
├── bg.js                # 背景形状层 + 章节标记 + 段落表 SECTIONS
├── player.js            # 预览播放器 + Web Audio 参考节拍
├── bundle.py            # 内联成一个 HTML
├── render.js            # CDP 逐帧导出
├── scenes/s1-pain.js …  # 一个场景一个文件
├── assets/ui/           # 界面切片（缩略图、对比图用真图）
├── assets/vo/           # 配音分句
└── render/              # 导出中间帧，不进版本库
```

改完源码跑 `python bundle.py` 重新生成单文件 —— 这样"给看片的人一个文件"
和"给自己分场景维护"两件事都不牺牲。

界面用 DOM 重画，不要整张截图贴上去 —— 片子里数字在跳、行在动，截图动不了。
只有缩略图和画质对比图用真图。

### 7.4 素材清单

- [ ] 100 BPM 配乐一段，且**能给到分轨**（鼓组一条、pad 一条），否则做不到"撤鼓"

### 7.5 导出

- **预览**：`index.html` 直接打开，`?t=毫秒` 定帧，不带参数实时循环。
- **成片**：无头 Chrome 按 `t = i × 1000/60` 逐帧调 `renderAt` 截 PNG，再交 ffmpeg 合成。

```
node render.js 0 69.6 60
ffmpeg -framerate 60 -i render/%05d.png -i mix.wav \
  -c:v libx264 -crf 16 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -movflags +faststart out.mp4
```

### 7.6 交片前检查

- [ ] 停顿段鼓组确实撤掉，不是音量压低

- [ ] 静音能看懂

- [ ] 无文字截断或省略号
- [ ] 中文字体预加载，`font-display: block`，无跳字
- [ ] `--accent` 面积目测 < 3%
- [ ] 1920×1080 / 60 fps / yuv420p / 时长 69.6 s

## 八、可选裁法

**要压到 60 秒以内**：收口从 12 拍砍到 8 拍（2 小节），全片 112 拍 = 67.2 s；
再砍 S7 与 S11 两个细节镜头，全片 96 拍 = 57.6 s —— 但这两个镜头是"丰富度"的主要来源。

**要更慢更贵气**：把每个功能段的细节镜头从 8 拍扩到 12 拍，全片 132 拍 = 79.2 s。
适合投官网而不是信息流。
